# EchoDay — 产品思路与模块功能计划

整理：Muse，2026-11-08。依据：已恢复的 Cursor 设计文档（README、apk-integration、platform-r2-supabase、muse_cloud.py）、muse-recorder PR #1、现有个人版流水线（R2 + 本地转写 + Supabase 日报），以及 Zhang 的确认：①要靠这个赚钱；②让用户配置自己的 AI；③**2026-11-08 晚定版**：另一个机器人 / Cursor 的源码只作参考、按本 PLAN 实施；**注册登录在 app 内完成**；**token 在 app 内发放**，用户把 token 粘给自己的 Muse 等 agent；agent 拉取范围**含照片**；回传的是**每天的图像 + 声音识别结果**，不只是汇总文字。

---

## 一、一句话定位

给 EchoDay 用的多用户云端：**用户只管录，云端只管存和展示，转写和总结用用户自己的 AI**。平台卖的是"省心的架子"，不是模型。

## 二、核心思路（为什么这样能赚钱）

1. **成本结构天然好**：最大的两块可变成本——转写和大模型——由用户自己的 key / 自己的 agent 承担。平台只剩存储和带宽：按现在 48 kbps、约 0.5 GB/天/人估算，R2 约 $0.015/GB·月。用户付 $5/月，毛利空间大。
2. **BYOK 是卖点，不只是省钱**：录音是最隐私的数据。"你的 AI、你的 key、你的账单"对目标用户（老板、记者、律师、销售管理者这类重度记录者）是信任卖点，也避开平台倒贴 token 钱、替用户背数据出境责任的问题。
3. **先自用、再小圈子、后公开**：第一版先让 Zhang 自己和朋友跑通（计费可走 stub），验证"注册→装 app→登录→上传→出日报"全链路，再开真实收费。不要一上来做大而全。
4. **数据留存要先想清楚**：个人版是"转写完就删云端原件"。付费用户不行——人家付钱买的就是存档。分档策略见下面专门一节（免费档靠"小额度 + 处理后清原件"逼出每日处理习惯；付费档才谈长期存档）。

### 免费额度与保留策略（Zhang 2026-11-08 定框架，数字为 Muse 建议值）

**核心机制一句话**：免费用户就 2 GB，存满就停存；想继续录，就必须让自己的 Muse 每天来把数据拉走、回传识别结果，平台随后清掉原件腾地方。不处理 = 录不下去，习惯就是这么逼出来的。

- **额度**：免费（含 7 天试用）**2 GB/人**，付费 **20 GB/人**。只统计原件（音频 + 照片 + 标记的字节数）；识别结果（汇总、转写、照片说明、活动图）**不计额度、永久保留**——成果永远在，压力只压在原件上。
- **为什么 2 GB 是"够用但紧"**：全天录音约 0.5 GB/天，快照压缩后约 0.1 GB/天，2 GB ≈ 3 天的量。天天处理的人根本碰不到顶；攒着不处理的人第 3 天就停存。
- **用满的行为**：新上传返回 `413 quota_exceeded`，app 明确提示"空间已满：让你的 Muse 处理一天并回传结果，或升级"；已存数据照常可读、可拉取，不扣留。
- **保留规则（平台每日 retention 任务执行）**：
  - **已处理的天**（agent 已回传该天 result）：原件在回传后保留 **2 天**（复核/补拉窗口），然后自动删除，只留结果。天天处理的人稳态占用约 1.3 GB，留有余量。
  - **未处理的天**：原件最长保留 **7 天**（免费档）。第 5 天起 app 内提醒"那天的录音还没被处理，2 天后删除原件"；满 7 天自动删原件（结果本来就没有），清单里标注已过期。注意实际先撞上的是 2 GB 硬墙（约第 3 天停存），7 天是清仓线，两个机制叠加。
  - **付费档**：已处理原件保留 30 天，未处理保留 90 天，规则同构、只是宽限长。
- **"确保有接收器在处理"的可见性**：app 首页和"连接我的 Muse"页都显示**上次拉取时间 / 上次回传时间**；超过 48 小时没有回传，app 内提醒一次（不轰炸）。用户一眼能看出自己的 Muse 还在不在岗，平台也能在后台统计"僵尸用户"。
- **删除的安全边**：retention 只删原件对象，永不删结果；删除按天整批执行并记日志，删错可查。

## 三、用户接入 AI：一个 API、一个 token（主形态，Zhang 2026-11-08 定调）

就是把 Zhang 现在和 Muse 的合作方式**反过来产品化**：

- **现在**：录音在 R2、文字存 Supabase——我的 Muse 要配两套凭证、连两个系统，才能"拉录音 → 转写 → 存汇总"。
- **产品形态**：R2 和数据库都藏到我们自己的 API 后面。用户的 Muse 只拿**一个 base URL + 一个 token**，拉和存都走这一个口。这就是用户要"配置"的全部，没有第二样东西。

### 给 agent 的 API（一共 6 个口，`/api/v1`）

| 接口 | 干什么 |
|---|---|
| `GET /api/v1/days` | 哪些天有数据、每段多少、有没有回传过识别结果（agent 靠它决定今天该处理哪天） |
| `GET /api/v1/days/{date}` | 一天的清单：录音段、自述、事件标记、**自动快照照片**列表，带各自的下载路径 |
| `GET /api/v1/files/{key}` | 下载音频/照片本体（带 token 鉴权） |
| `PUT /api/v1/days/{date}/result` | 回存**每日识别结果**（声音 + 图像一次交齐）：汇总正文、转写稿、分段分析、照片识别说明（逐活动簇的文字说明），分开字段、幂等覆盖 |
| `PUT /api/v1/days/{date}/sheet` | 上传每日活动图（agent 拼好的约 1 MB 缩略图墙 JPEG），app 日报页和网站直接展示 |
| `GET /api/v1/days/{date}/result` | 读回已存的识别结果（agent 查重；用户侧 app 日报页 / 网站在读同一份） |

（手机上传走 app 自己的账号登录 `PUT /api/v1/upload/{key}`，不占这个 token——分工是：**人/手机用账号，AI 用 token**，两边都只有一个凭证。）

### Token 设计：一把全权钥匙

- 每个用户默认就一个 token，权限 = 对自己数据的**读（拉）+ 写（存汇总）**，不再让用户理解五种 scope；`api_tokens` 表里的 scopes 字段保留作高级限制，默认全开。
- 在 **app 内「连接我的 Muse」页**生成和显示（网站同账号镜像一份）；只完整显示一次、库里只存 hash；泄露了在 app 里一键吊销重发，旧的立刻失效。
- token 只能碰到本人数据，服务端按 token 反查 user_id 做隔离。

### 接入动作：复制一段话

app 内"连接我的 Muse"页给三样东西：base URL、token、一段现成话术，全部带一键复制。用户把话术粘给自己的 Muse 就完事——**注册、登录、拿 token 全在 app 里闭环，不需要先上网站注册**。话术内容就是我现在每天对 Zhang 做的流程写成指令：定时拉未处理的天 → 拉音频 + 照片 → 本地转写 + 照片识别 → 自述置顶、按标记切分 → 汇总、照片说明和活动图一起回存。再配 `muse_cloud.py` 参考脚本（按上面 6 个口更新），会写脚本的 agent 可直接调。

**好处**：平台不碰模型、没有 token 成本和欠费风险；用户换任何 agent / 模型都行；接入文档就一页。

### 兜底形态（不是主线，别先做）

- **没 agent 的用户**：二期可加"填自己的模型 API key、平台 worker 代跑"（配置存 `user_ai_configs` 表，`schema.sql` 已备），等有真实需求再做。
- **什么都不配**：平台只存只看，无转写无汇总，随时粘 token 升级。

## 四、模块清单

### 1. 账号与计费
- **注册/登录主入口在 app 内**：app 里直接邮箱 + 密码注册（注册即开 7 天试用）、登录、登出（JWT + `token_version` 踢下线）；网站用同一账号登录、只作查看镜像，不承担注册入口；改密/找回走邮件链接（二期）
- app 内"我的"页显示试用剩余天数 / 订阅状态；到期停上传（402）时在 app 内提示，并给出续费入口（打开 Stripe Checkout 网页完成付款）
- 7 天试用；到期停上传（402）、不删数据、可续费恢复
- Stripe 订阅 $5/月：Checkout、Customer Portal、webhook 同步状态；无 Stripe 时走 stub 模拟全流程
- 管理员可手动改单个用户的订阅状态（送朋友、先行内测用）

### 2. 录音接入（app 侧）
- PR #1 的云端登录/上传适配到现版 app（PR 基于 v1.10.0，现版 v1.15.0，要移植不能直接合并）
- app 设置里"云端模式 / 自己的 R2 模式"二选一；云端模式只填服务器地址+登录，零密钥。**产品版默认云端模式**：装好 app → 注册/登录 → 直接开录上传，用户全程不接触任何密钥配置；app 日报页改读平台的每日识别结果（汇总 + 照片识别 + 活动图），不再直连 Supabase
- 上传沿用现有对象 key 布局、断点重传和失败重试

### 3. 存储层
- 驱动三选一：本地文件 / S3 兼容（MinIO）/ Cloudflare R2，都按 muse-recorder 现有 key 布局
- 每用户隔离（key 前缀或独立校验），配额统计（每用户已用容量可查）
- **配额硬顶**：上传时实时查用量，超额返回 413（免费 2 GB / 付费 20 GB，环境变量可调）；只统计原件，结果不计
- **留存任务（每日 retention）**：按第二节策略删原件——已处理的天在回传 2 天后删（付费 30 天），未处理的天满 7 天删（付费 90 天）；只删原件对象、永不删结果，删除记日志

### 4. 数据层
- Postgres 7+1 张表（`schema.sql`）：users、api_tokens、days、day_objects、markers、summaries、supabase_identity_links（可选集成，先关）、user_ai_configs（新增）；summaries 已扩字段：分段分析、照片识别说明、活动图 key——每日识别结果（声音 + 图像）整存一处
- 录音/照片本体不进数据库，只存对象元数据

### 5. 网站
- 天列表（日期、段数、时长、容量、有无汇总）、按关键词搜索（汇总正文+标记+文件名）
- 天详情：音频播放器（Range 拖动）、标记时间线、照片墙、汇总正文（Markdown 渲染）、转写稿
- 汇总可在线编辑；天详情显示"你的 Muse 上次回存时间"
- 每日活动图（agent 回传的 sheet）直接展示，与 app 日报页同一份数据、两边一致

### 6. "连接我的 Muse"页面（在 app 内，第三节落地，即本产品的差异化模块）
- 一页三样：base URL、token 生成/吊销/重发、现成话术，全部一键复制；显示"你的 Muse 上次来拉数据/回存结果的时间"，让用户确认接通了
- 网站放同样的页面作镜像（同一账号），但 onboarding 以 app 内为准
- 二期才加：模式 B 的 key/模型配置表单

### 7. Agent 接口
- 第三节的 6 个口，`/api/v1` 版本化；token 全权读写本人数据，hash 存、只显示一次、可即时吊销；拉取含照片，回存收每日识别结果（声音 + 图像）
- 参考实现 `muse_cloud.py`（拉一天/存汇总两个子命令），随接入页一起给

### 8. 转写与总结 worker（二期可选，不进主线）
- 仅当要支持"填 key 平台代跑"时才做：定时扫未处理的天，用该用户 key 转写+总结后写回 summaries，规则复用个人版（自述置顶等），任务状态和失败原因可查

### 9. 通知
- 日报完成通知：先做站内+邮件（二期再考虑微信/推送）
- 试用到期前 2 天、订阅扣款失败、AI key 失效，各通知一次，不轰炸

### 10. 管理后台（最小版）
- 用户列表、订阅状态、每用户存储用量、全局容量；手动开通/停用账号。就够了，别做复杂。

### 11. 安全与合规
- 密码 hash、JWT、token 只存 hash、用户 key 加密存——这四条是底线
- 每用户数据严格隔离，所有查询带 user 条件（Cursor 版在 Supabase 上栽的就是这个：表没 owner 列；我们 Postgres 原生带 user_id，没这问题）
- 账号注销=数据真删（录音、转写、汇总、key 一并删），给用户导出 zip（二期）
- 录音合法性提示：注册和 app 首次开启云端模式时，提示用户遵守当地录音同意规则

### 12. 部署与运维
- Docker Compose 一键起（web+api+postgres+对象存储），VPS 一台够
- 域名+HTTPS（Caddy 反代），数据库和对象存储定期备份
- 健康检查 + 磁盘/容量告警（先发给 Zhang 自己）
